## Evidence types and platform boundaries

- **Deterministic policy/model tests:** immutable values, configuration, request/response transformations, controlled clocks, scripted transports/providers/sinks, and direct delegate callbacks. Available in each selected runtime but do not establish actual network/OS timing behavior.
- **Native URLSession with URLProtocol:** request assembly, ownership and cancellation on macOS/iOS/tvOS. watchOS uses explicitly scripted adapter I/O or public construction/identity checks where interception is unsupported. These tests do not validate a certificate chain or wire storage.
- **Native controlled-server probes:** RedirectIntegrationTests and the three strict-storage/challenge probes use actual macOS URLSession plus isolated local Python HTTP fixtures. Other platform branches use documented scripted/configuration checks. S03/S06 therefore have stronger native wire evidence on macOS only. Direct terminal-callback cancellation tests use never-resumed tasks and are deterministic, not network evidence.
- **Actual minimum runtimes and physical devices:** not established by newer CI destinations or any of the preceding categories. See [environment readiness](ENVIRONMENT_READINESS.md).

Response metadata is preserved as Foundation exposes it, not raw wire ordering/repetition. No synchronous coding callback has a hard real-time interruption guarantee. No library retry/refresh, arbitrary decoder plugin, streaming, background transfer, advanced TLS or path-monitor feature is added to make a deferred requirement appear covered.

## Fixture isolation and concurrency review

The suite has two shared registries: `SessionStubProtocol.fixtures`, locked and keyed by a fresh UUID URL, and `BudgetDecoding.clocks`, locked and keyed by UUID encoded into that test's payload. Mutable fixtures, gates, clocks, callbacks and account state belong to individual operations/tests; registrations are removed with defer. There is no single mutable global response/handler or URLProtocol.registerClass installation. Reading shared cookie/credential store identities to reject unsafe combinations is not permission to write or clear them; storage positive controls assert private-store identity before mutation.

This is scoped isolation through synchronized registries, not a claim that no static object exists. No test may clear the whole registry or reuse another test's key. Callback invocation occurs outside registry/gate locks. Explicit concurrent-call/account/codec tests in L01–L11 and S10/S13 verify isolation even where a test runner uses one process. The local parallel suite exercises the existing fixtures together; it is not Thread Sanitizer, an exhaustive schedule exploration or proof of arbitrary app callback safety. Keep the hosted process/test-runner configuration unchanged.
