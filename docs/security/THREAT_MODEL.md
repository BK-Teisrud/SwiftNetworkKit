# NetworkKit v1 threat model

Reviewed 2026-10-26 for I19 / #60 against the HTTP core after QA-01 / #97. Maintainer review, not an independent security audit. The [security/privacy review](../planning/SECURITY_PRIVACY_REVIEW.md) records evidence and unresolved release gates. Reassess after changes to transport, origins, authentication, storage, diagnostics, dependencies or platform support.

## Assets, actors and boundaries

Assets are app credentials, account/environment binding, request/response confidentiality and integrity, caller cancellation, session ownership and sanitized diagnostics. An attacker may control an endpoint response, redirect target, response size/timing, or an untrusted network. Caller input may be malformed. The host app, its provider/sink, injected session and operating system are trusted collaborators; NetworkKit cannot sandbox malicious app code or a compromised process/device.

Data flows from a typed endpoint or raw URLRequest through validated preparation, an optional app-owned authentication provider, the per-operation lifecycle and URLSession adapter, the network and response validation/decoding back to the app. Both inputs share these boundaries. Diagnostics branch only after joined operation cleanup into an optional local app-owned sink. An explicitly app-managed borrowed session may retain cookies/cache under app control. No independent SDK telemetry endpoint, persistent payload store or token store exists.

## Threats, controls and evidence

| ID | Threat | Implemented control and regression evidence | Residual boundary / owner |
| --- | --- | --- | --- |
| T1 | Initial destination substitution or ambiguous URL parsing | Structural URL validation; exact normalized scheme/host/effective-port permissions; typed/raw preparation parity. EndpointURLTests and NetworkSecurityTests, including `deniedInitialDestinationsNeverReachDataOperation` | App chooses trustworthy permitted origins; URL permissions do not filter server-side destinations. #60 review / #62/#63 native evidence |
| T2 | Redirect credential exfiltration or unsafe mutation replay | Only same-origin, same-method GET/HEAD; five-hop bound; terminal loop cancellation; no inherited defaults/provider on separately permitted raw origins. RedirectIntegrationTests; AuthenticationTests.`redirectCannotMoveProviderCredentialsToAnotherOrigin` | Native macOS loopback evidence is HTTP; native HTTPS/other runtimes remain #62/#63 |
| T3 | Network interception or implicit challenge credentials | HTTPS default; system server-trust handling; other challenges cancelled with nil credentials; external session delegates and credential stores rejected. NetworkSecurityTests.`challengeCallbacksDiscardEvenProposedCredentials` | Callback tests do not prove native TLS. System-trusted success, invalid trust and hostname mismatch require ENV-02 evidence, #62/#63 |
| T4 | Credential disclosure through local HTTP | Explicit loopback-only opt-in; no provider, sensitive/custom headers or active automatic stores. NetworkSecurityTests and AuthenticationTests.`httpNeverInvokesProvider` | A caller can conceal secrets in a body/query/allowed metadata. App must not do so; local HTTP is credential-free development only |
| T5 | Account confusion or unintended cookie/cache persistence | Strict owned/borrowed settings; explicit app-managed profile; foreign-origin cookie-store rejection; immutable provider binding and conflict rejection. StorageIntegrationTests, SessionTransportTests, AuthenticationTests | App owns account isolation and deletion of opted-in stores; borrowed/custom session behavior is trusted. #62/#63 extend native evidence |
| T6 | Secret leakage in errors or diagnostics | Fixed event fields, safe error categories and descriptions; no automatic raw logging/file writes. DiagnosticsTests.`canariesInEveryBoundaryStayOutOfEventsAndErrorDescriptions` and `unknownErrorsAreClassifiedWithoutFormattingThem` | Request/response values intentionally returned to the app can contain sensitive data. App sinks, codecs, OS/proxy/crash logs require their own review |
| T7 | Stalled work, race corruption or cross-client shutdown | Monotonic total budget; first terminal selection; scoped cancellation and admission; joined worker/watchdog cleanup; no app callbacks under locks. OperationBudgetTests and ClientLifecycleTests | Cooperative app callbacks/encoding/decoding cannot be forcibly preempted. No hard realtime guarantee; physical network transitions remain #63 |
| T8 | Memory/resource exhaustion by large buffered data or concurrency | Bounded logical operation lifetime and redirect count; cleanup tests | Buffered v1 has no response-size cap or concurrency limiter. #61 must measure and document safe use; unacceptable results require a bounded fix before release |
| T9 | Supply-chain or distribution drift | No external package dependencies; pinned Actions, read-only CI permissions, required checks; bundled privacy manifest regression | Rules can be edited by the account owner. #64/#86 must verify the final archive, aggregate privacy report and exact release candidate; CI does not certify distribution |

No severe implementation finding was identified in this bounded source review. This does not establish absence of vulnerabilities or owner acceptance of residual risk. Severe future findings block release; use the private reporting process in [SECURITY.md](../../SECURITY.md). Known unverified native/platform/resource/distribution behavior remains open under existing release tasks, not accepted by a passing unit test.
